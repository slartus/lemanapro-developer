# mr-watch — отмена устаревшего ревью при новом коммите (2026-11-09)

Фича: отмена устаревшего ревью при новом коммите в MR.
Ветка: feat/supersede-stale-review (не закоммичено).
Профиль: feature (research → plan → executing → validation → report).

## Задача
Пользователь спросил, что происходит, если в MR появился новый коммит во время ревью.
- Раньше: старое ревью доживало и завершалось по старому head; новое ревью запускалось только при включённом флаге `re_review_on_push`.
- Решение пользователя: отменять устаревшее ревью и запускать новое ВСЕГДА, независимо от `re_review_on_push`.

## Research (консилиум)
- Архитектор:
  - реестр задач ревью в памяти, БД — источник истины;
  - новый статус `cancelled` (миграция v10);
  - обработка смены head на всех путях поллера (todo / full_scan / sweep);
  - найдено: todo-путь мог «съедать» `head_sha_changed` раньше sweep;
  - `queued` перебазируется на новый head.
- Безопасность:
  - отменять отдельную задачу ревью, а не цикл worker'а;
  - условные UPDATE;
  - shield для удаления клона;
  - риски: потомки opencode вне группы процессов, отсутствие debounce при частых push, SIGKILL без грейса для opencode, tmp opencode не чистится.
- Фронтенд:
  - отдельный статус `cancelled` лучше `error` (нейтральный, не засоряет фильтр error);
  - вердикт берётся из последнего `done` и не затирается.

## Реализация (по файлам)
- `db.py`:
  - `SCHEMA_VERSION` = 10;
  - пересоздание таблицы `review` с CHECK, включающим `cancelled`;
  - `supersede_reviews` (возвращает `SupersedeResult`);
  - условные `finish_review`, `mark_reviewing`, `requeue_review`, `rebase_review_head`;
  - `retry_review` работает из `cancelled`.
- `worker.py`:
  - `ReviewRegistry`;
  - ревью выполняется в отдельной задаче;
  - отмена ревью не убивает worker;
  - остановка worker'а пробрасывается дальше;
  - удаление клона выполняется под shield.
- `poller.py`:
  - `_supersede_stale` вызывается во всех трёх путях (todo / full_scan / sweep);
  - новое ревью с `trigger=push` создаётся для открытого MR без проверки mine и без учёта флага `re_review_on_push`;
  - дедупликация enqueue.
- `main.py`: общий реестр между компонентами.
- Шаблоны (`base.html`, `index.html`, `review.html`):
  - бейдж и фильтр для статуса `cancelled`;
  - плашка «Ревью отменено»;
  - кнопка Re-review для `cancelled`.
- `README.md`, `docs/CHANGELOG.md`: описание поведения и запись в changelog.

## Открытые вопросы и риски
- Падение процесса между `upsert_mr` и `supersede_reviews` приводит к потере смены head: при следующем проходе поллер может не увидеть изменение.
- После рестарта `requeue_incomplete` возвращает активные ревью в `queued` на старом sha. Они отработают по старому коммиту: при claim нет сверки `review.head_sha` с `mr.head_sha`.
- Не сделано из рекомендаций безопасности:
  - debounce и лимиты на количество отмен при частых push;
  - потомки opencode вне группы процессов;
  - SIGTERM-грейс перед SIGKILL для opencode;
  - очистка tmp-директорий opencode.
- Решение по `re_review_on_push` больше не влияет на поведение при новом коммите; если флаг нужен для других сценариев, его семантику стоит пересмотреть отдельно.
