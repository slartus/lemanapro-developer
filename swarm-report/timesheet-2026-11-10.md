# Таймшит — предложения по списанию времени в Yandex Tracker (2026-11-10)

Фича: вкладка «Таймшит» в левой панели по мотивам diarworld/timesheeter.
Ветка: feature/timesheet → main (e0c60a3), выкачено `deploy/update.sh`.
Профиль: business-feature (research → plan → executing → validation → report).
Статус: Done.

## Задача
Таблица на неделю «задачи × дни» с предложениями, сколько часов в какую задачу
списать, без аналитики — просто раскидать рабочие часы. Решения пользователя:
- сигналы — активность GitLab + задачи Tracker;
- кнопка «Списать» пишет worklog в Tracker;
- неделя, норма 8 ч + производственный календарь РФ, шаг 0.5 ч;
- списывать можно с понедельника прошлой недели, очередь SUPERAPP;
- активность без ключа только показывается, комментарий к worklog не пишется.

## Research (консилиум)
- Архитектор: GitLab Events API, ключ задачи из ветки/заголовков, Tracker
  `/worklog/_search`, `/issues/_search`, календарь — JSON в репозитории.
- Безопасность: маскирование `OAuth`/`y0_`, общая проверка `X-Requested-With`,
  журнал списаний с идемпотентностью, серверная валидация.
- UI: пункт в панели, состояния ячеек, диалог подтверждения, мобильная раскладка.

## Реализовано
- Backend: `tracker_client.py`, `timesheet.py` (`allocate`, `suggest_day`,
  `status_intervals`), `workcalendar.py`, `web/timesheet_routes.py`,
  миграции v13/v14, `tracker:` в конфиге (токен из Keychain).
- Frontend: `timesheet.html`, `timesheet.js`, `timesheet-model.js`.
- Связь MR ↔ задача: заголовок, ветка, комментарии Tracker со ссылкой на MR
  (бот `ya360-pr-check` или человек), `Closes KEY` в описании.
- Только своя работа: чужие MR, интеграционные ветки и merge-коммиты не
  учитываются.
- Предложение = доля нормы дня минус уже списанное на задачу.
- Статус задачи и интервалы статусов в строке; списание одной ячейки (✓ / +)
  с предупреждением о статусе; индикатор загрузки.
